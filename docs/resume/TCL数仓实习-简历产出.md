## 一、项目定位

**项目名**:基于 Hadoop 生态的电商数仓

**一句话概括**:
TCL 实习项目,用 Hadoop 生态(Hive/Spark/Sqoop/Kafka/Flume/DolphinScheduler)做电商业务数仓,数仓分层(ODS/DWD/DWS/ADS)沉淀每日 100G+ 业务数据,8 个主题域 50+ 业务指标,支持 Superset 业务报表。

**技术栈**:
Hadoop · Kafka · Flume · Zookeeper · Hive · Spark · Sqoop · Presto · DolphinScheduler · Superset · MySQL

**需求背景**:
电商业务系统(MySQL 业务库)数据多源、格式不一,需要沉淀到数仓做下游分析;传统数仓按业务系统分表,数据口径不统一、查询慢(5min+)、Spark 跑批受数据倾斜影响。

---

## 二、核心亮点（5 条,STAR 法则）

### 亮点 1 · 数仓分层设计 + 8 主题域 + 50+ 业务指标
和业务部门对接需求,设计 **ODS / DWD / DWS / ADS** 四层数仓架构,统一数据口径;沉淀 8 个主题域(销售 / 用户 / 商品 / 库存等),开发 50+ 业务指标(日销售额 / 用户复购率 / 商品动销率等)。

### 亮点 2 · Sqoop 每日增量同步 + Hive 清洗构建 DWD
用 Sqoop 每日从 MySQL 同步到 ODS 层(增量 + 全量);HiveSQL 做数据清洗与基础加工,构建 DWD 层核心表;**日均数据量 100G+**。

### 亮点 3 · Spark 复杂 ETL 优化,跑批效率 +30%
Spark + Hive 协同做复杂 ETL,SparkSQL 优化中间层计算流程;**整体跑批效率提升 30%**。

### 亮点 4 · 维度建模宽表设计
基于维度建模理论,设计销售主题宽表(销售明细宽表、用户行为宽表),计算核心业务指标(销售 / 复购 / 动销等);**50+ 业务指标覆盖销售 / 用户等主题域**。

### 亮点 5 · DolphinScheduler 调度 + Superset 可视化
DolphinScheduler 定时跑 ETL 任务,Superset 拉 ADS 层做业务报表展示。

---

## 三、项目难点(3 条)

### 难点 1 · 数据倾斜:Spark Shuffle 优化
用户行为数据分布不均 → Spark Shuffle 阶段耗时过长。方案:**随机前缀打散热点 + 调 Spark Shuffle 参数 + Broadcast Join 优化关联逻辑**;任务执行时间大幅缩短。

### 难点 2 · ADS 报表查询慢:Presto + 预计算,5min → 30s
报表查询响应时间 5 分钟影响业务。方案:**ADS 层宽表加预计算字段 + Presto 高性能查询引擎**;**查询时间从 5 分钟优化到 30 秒,效率提升 90%**。

### 难点 3 · Flume 数据漂移 + 小文件
Flume 同步 Kafka 到 HDFS 2 个问题:
- **数据漂移**:自定义 Kafka Source 的 Interceptor,把 event header 时间戳字段替换成 body 里的日志生成时间,HDFS Sink 基于 event 时间戳落盘
- **小文件问题**:配置 `hdfs.rollInterval` / `hdfs.rollSize` / `hdfs.rollCount` 限制新文件生成

## 五、面试深挖备用

| # | 面试官常问 | 答到哪句话算稳 |
|---|---|---|
| 1 | ODS/DWD/DWS/ADS 各自存什么 | ODS 原始数据(同步上来不改)/ DWD 清洗后明细(去重/去空)/ DWS 轻度汇总(主题聚合)/ ADS 应用层(指标宽表) |
| 2 | 为什么用 Sqoop 不直接 MySQL JDBC | Sqoop 是 MR 跑的,可以并行;大数据量稳定;Sqoop 增量 + 全量两种模式;JDBC 不适合 100G+ 数据 |
| 3 | Spark Shuffle 数据倾斜怎么排查 | 看 Spark UI 的 Stage 详情,看 task 处理的数据量,某个 task 远大于其他 → 数据倾斜 |
| 4 | 怎么解决数据倾斜(具体方案) | 随机前缀打散 + 调 Shuffle 参数 + Broadcast Join(小表) + Salting(加盐) + 单独处理热点 key |
| 5 | Flume 数据漂移怎么发生的 | event header 时间戳是 Kafka Source 默认带的(可能不是日志生成时间),HDFS Sink 用 header 时间戳落盘 → 数据按错误时间落到错误分区 |
| 6 | Presto 为什么比 Hive 快 | Presto 是 MPP 架构(内存计算、流水线、不落盘),Hive 是 MR 架构(每步落盘);Presto 适合亚秒-秒级查询,Hive 适合分钟级批处理 |
| 7 | 数仓为什么不直接放 MySQL | MySQL 单机存储,扛不住 100G+;数仓用列存(Parquet/ORC)+ 分区,扫描只读相关列,效率高;MySQL 行存,全表扫 |
| 8 | 50+ 业务指标怎么保证口径一致 | 在 DWD 层统一字段命名(同名字段同义)+ DWS 统一计算逻辑 + 业务方 review 指标定义 |
