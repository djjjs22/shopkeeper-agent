> 风格对齐参考简历的口径:项目背景 → 技术架构 → 个人职责 → 项目难点;亮点用问题 → 方案 → 收益三段式。

## 一、项目定位

**项目名**:三喜生活数仓建设(2024-12 ~ 2025-02)

**一句话概括**:
行为日志用 Flume/Kafka 采到 HDFS,业务数据用 DataX/MaxWell 从 MySQL 全量 / 增量同步;数仓五层(ODS/DIM/DWD/DWS/ADS)分层架构,基于 DolphinScheduler 定时调度监控。

**技术栈**:
Hadoop · Kafka · Flume · Zookeeper · Hive · Spark · DataX · MaxWell · DolphinScheduler · MySQL

**需求背景**:
三喜生活电商业务数据多源(行为日志 + 业务 MySQL 库),需要沉淀到数仓做下游分析;传统数仓按业务系统分表,数据口径不统一、查询慢(5min+),需要规范化的分层架构和定时调度。

---

## 二、核心亮点（5 条,STAR 法则）

### 亮点 1 · 数仓分层设计 + 8 主题域 + 50+ 业务指标
和业务部门对接需求,设计 **ODS / DIM / DWD / DWS / ADS** 五层数仓架构,统一数据口径;沉淀 8 个主题域(销售 / 用户 / 商品 / 库存等),开发 50+ 业务指标(日销售额 / 用户复购率 / 商品动销率等)。

### 亮点 2 · 多源数据采集 + Sqoop/DIM 维表层
行为日志用 Flume/Kafka 采集到 HDFS;业务数据用 DataX、MaxWell 从 MySQL 全量 / 增量同步至 HDFS;新增 DIM 维表层存业务维度数据,降低后续 JOIN 复杂度。

### 亮点 3 · Spark 复杂 ETL 优化,跑批效率 +30%
Spark + Hive 协同做复杂 ETL,SparkSQL 优化中间层计算流程;**整体跑批效率提升 30%**。

### 亮点 4 · 维度建模宽表设计
基于维度建模理论,设计销售明细宽表、用户行为宽表;计算核心业务指标(销售 / 复购 / 动销等);**50+ 业务指标覆盖销售 / 用户等主题域**。

### 亮点 5 · DolphinScheduler 调度 + ADS 同步 MySQL
DolphinScheduler 定时跑 ETL 工作流 + 监控告警;**ADS 层结果同步到 MySQL 支撑下游应用**。

---

## 三、项目难点(3 条)

### 难点 1 · 数据倾斜:Spark Shuffle 优化
用户行为数据分布不均 → Spark Shuffle 阶段耗时过长。方案:**随机前缀打散热点 + 调 Spark Shuffle 参数 + Broadcast Join 优化关联逻辑**;任务执行时间大幅缩短。

### 难点 2 · ADS 报表查询慢:Presto + 预计算,5min → 30s
报表查询响应时间 5 分钟影响业务。方案:**ADS 层宽表加预计算字段 + Presto 高性能查询引擎**;**查询时间从 5 分钟优化到 30 秒,效率提升 90%**。

### 难点 3 · Flume 数据漂移 + 小文件
Flume 同步 Kafka 到 HDFS 2 个问题:
- **数据漂移**:自定义 Kafka Source 的 Interceptor,把 event header 时间戳字段替换成 body 里的日志生成时间,HDFS Sink 基于 event 时间戳落盘
- **小文件问题**:配置 `hdfs.rollInterval` / `hdfs.rollSize` / `hdfs.rollCount` 限制新文件生成

## 五、面试深挖备用

| # | 面试官常问 | 答到哪句话算稳 |
|---|---|---|
| 1 | ODS / DIM / DWD / DWS / ADS 各自存什么 | ODS 原始日志 / DIM 维表(城市/产品/时间)/ DWD 清洗明细 / DWS 轻度汇总 / ADS 应用层(指标宽表) |
| 2 | DIM 维表层怎么维护 | 全量初始化 + 每日增量(基于时间戳)+ SCD Type 2(缓慢变化维) |
| 3 | DataX / MaxWell / Sqoop 怎么选 | DataX 通用、MaxWell 监听 MySQL binlog 实时增量、Sqoop 大数据量全量/增量 |
| 4 | 行为日志为什么要先到 Kafka 再到 HDFS | Kafka 解耦(消费方可以多个,流式 + 批式都能消费)+ 重试(避免日志丢失)+ 削峰 |
| 5 | ADS 同步到 MySQL 怎么增量 | 用时间戳增量(根据 last_update_time)+ 业务主键 UPSERT |
| 6 | Spark Shuffle 数据倾斜怎么排查 | 看 Spark UI 的 Stage 详情,看 task 处理的数据量,某个 task 远大于其他 → 数据倾斜 |
| 7 | 怎么解决数据倾斜(具体方案) | 随机前缀打散 + 调 Shuffle 参数 + Broadcast Join(小表) + Salting(加盐) + 单独处理热点 key |
| 8 | Flume 数据漂移怎么发生的 | event header 时间戳是 Kafka Source 默认带的(可能不是日志生成时间),HDFS Sink 用 header 时间戳落盘 → 数据按错误时间落到错误分区 |
| 9 | 小文件怎么影响后续 | NameNode 内存压力大(每个文件一个 block 元数据)+ MapReduce 任务多(每个文件一个 map) |
| 10 | DolphinScheduler 怎么保证 DAG 不重跑 | 任务依赖关系(下游等上游成功)+ 自依赖(防止自环)+ 失败重试 + 告警 |
